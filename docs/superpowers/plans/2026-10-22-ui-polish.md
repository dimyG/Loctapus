# UI Polish Round - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the ten UI remarks from the 2026-10-22 review: open uploaded files in a new tab, toolbar spacing, a labeled project dropdown, a ChatGPT-style chat composer, notch-fixed form labels, a status spinner, a centered single hero CTA, richer marketing copy, the Loctapus name, and the octopus logo.

**Architecture:** Pure frontend restyling on the existing MUI-template UI, plus one read-only backend endpoint (`GET /api/projects/{project_id}/uploads/{upload_id}/raw`) that returns a stored upload's bytes so the SPA can open them in a blob-URL tab (a plain link cannot carry the bearer token).

**Tech Stack:** FastAPI + SQLAlchemy + boto3/Garage (backend); React 19, MUI v9.5, react-router 8, RTK Query, Vitest + Testing Library + MSW, Playwright (web).

**Spec:** `docs/superpowers/specs/2026-10-22-ui-polish-design.md` (read it first; this plan argues from it).

## Global Constraints

- No backend changes beyond the one raw endpoint of Task 1: no schema, migration, or pipeline changes. `web/src/test/handlers.ts` baseline stays untouched; tests override endpoints with `server.use(...)` only.
- Copy rules (exact values from the spec): wordmark "Loctapus" (title case) everywhere the "RAG" wordmark appears today; the dropdown caption reads "Project"; coming steps carry a "Coming" chip; the open-failure snackbar reads "Could not open the file."; the hero title is "Chat with your company's knowledge base"; the subtitle is verbatim "Deploy AI teammates that understand your data, product, knowledge, and tools. A private workspace where your team stores its documents and asks questions in everyday language."
- The logo is committed unmodified as `web/public/logo.png` from `D:\Downloads\Blue Chat Octopus Logo.png` (1254x1254 RGBA, transparent background, verified in the spec); no image processing. The favicon is the provided package `D:\Downloads\favicon_io.zip` extracted unmodified into `web/public/`, with its `site.webmanifest`'s empty `name`/`short_name` set to "Loctapus".
- Chat source chips are small subtle labels: `Chip size="small" variant="outlined"` labeled `[i] filename` in a wrapping row; clicking a chip opens a small dialog titled with the full `[i] filename > path` label showing the chunk text.
- Accessible names preserved so existing tests and e2e keep their selectors: the chat input keeps label "Ask a question", the send control keeps accessible name "Ask" (a circular `IconButton` with `aria-label="Ask"`), the project `Select` keeps `aria-label="Project"`.
- Comments start with a capital letter and end with a dot; explain why, not what. No em dashes anywhere.
- `web/tsconfig.app.json` sets `verbatimModuleSyntax: true`: type-only imports must use `import type`, and neither lint nor vitest type-checks - every web task runs `npx tsc -b`.
- jsdom quirks (carry-over from the template port): responsive `sx` values resolve to the xs value, so CSS-hidden elements need `{ hidden: true }` queries; jsdom does not implement `URL.createObjectURL` / `revokeObjectURL` - stub them with `vi.stubGlobal` in the Task 9 tests.
- Verification per web task, in `web/`: `npx vitest run <focused files>`, `npm run lint`, `npx tsc -b`, `npm run format:check`, then the full `npm test` before the task's commit.
- Verification per backend task, in `backend/` with the compose stack up (the suite uses the real Garage and the `rag_test` database): `ruff check .`, `ruff format --check .`, `mypy app tests`, `pytest`.
- One concern per commit; commit messages follow the repo's `type(scope): summary` style.
- Known vitest flakiness under parallel load: re-run a single failing file before treating a failure as real.
- Python style: 110-char lines, every function docstringed (private too, with a blank line after the docstring), keyword-only parameters, no positional calls.

## Review Focus

Failure classes the spec implies that per-task tests could miss - each is pinned by the named test:

1. A filename clicked twice while the first open is still in flight must fire one fetch and one `window.open`, not two. Pinned in Task 9, `SourceItemsTable` "ignores a second click while the open is in flight".
2. An upload id that belongs to a different project the user can see must 404 "upload not found" - the item lookup is scoped by project, never cross-project. Pinned in Task 1, `test_upload_raw_unknown_or_other_project_item_returns_404`.
3. The item row exists but its bytes are gone from Garage must 404 "file not found" - distinct from a storage outage, which is 503. Pinned in Task 1, `test_upload_raw_missing_object_returns_404` and `test_upload_raw_storage_failure_returns_503`.
4. A whitespace-only chat input keeps the Ask control disabled (the trim gate), exactly like an empty one. Pinned in Task 8, `ChatPanel` "keeps Ask disabled for empty and whitespace-only input".
5. Terminal statuses render no spinner while every non-terminal one does - not just the queued fixture. Pinned in Task 7, `UploadStatusChip` "shows a spinner for every non-terminal status and none for terminal ones".

In `backend/app/sources/service.py`:

```python
def get_upload_item(*, db: Session, project_id: UUID, upload_id: UUID) -> SourceItem | None:
    """Return the project's upload item with this id, if any."""
```

Same join/where shape as `_upload_item`, but filtering `SourceItem.id == upload_id` instead of the filename.

In `backend/app/sources/router.py`, add after `list_all` (import `Response` from fastapi and `ObjectNotFoundError`, `get_upload_item` from their modules):

```python
@router.get("/projects/{project_id}/uploads/{upload_id}/raw")
def download_raw(
    *,
    project_id: UUID,
    upload_id: UUID,
    user: User = Depends(get_current_user),
    db: Session = Depends(get_db),
    storage: StorageService = Depends(get_storage),
) -> Response:
    """Return the upload's stored bytes, raising 404 or 503."""
```

Body: `get_project_visible_to_user` else 404 "project not found"; `get_upload_item` else 404 "upload not found"; `storage.get_object(key=item.raw_object_key)` mapping `ObjectNotFoundError` to 404 "file not found" and `StorageUnavailableError` to 503 "Could not load the file. Please try again."; return `Response(content=..., media_type=item.content_type, headers={"Content-Disposition": f'inline; filename="{item.filename}"'})`. `inline` so the new tab renders PDFs instead of forcing a download.
